# Analytics Data Marts — contract `powerbi-marts-1`

06/11/2026; baseline `feat(gold)@cd2f1a77b27d5bcba6f1d925e3d9305952551bae`.
This design defines the implemented eight-mart report export; it does not change canonical Gold. Actual acceptance is recorded in [DATA_MART_VALIDATION.md](DATA_MART_VALIDATION.md).

Marts are typed CSV serving datasets in a new immutable `exports/powerbi/<batch>_<timestamp>_<id>/` bundle. They consume `iceberg.gold_local` through `ExportSession → EDAClient → Analytics admission → Gold read_window`. No Spark job, Iceberg table, database, service or DAG is added. Old v1 bundles and their four schemas remain supported. A v2 bundle contains ten CSVs representing eight subject marts, the exact published snapshot context and final publication fence.

Source/source-geography/product keys are retained; labels do not create cross-provider conformance. Marts retain declared scope in their manifest, SQL definition/version/compiled hashes and per-cell observation lineage. Existing NSO exports retain release-status counts in the manifest; Gold PUBLISHED does not make provisional/unconfirmed source values final.

Executable contracts live in `src/analytics/marts/`: schemas, keys, admitted domains/units, pairing/missing rules and coverage checks. The offline verifier rechecks these and recomputes derived fields, in addition to checksum/roundtrip integrity. A checksum alone cannot certify semantic correctness. Original observations never change to match EDA references.

All query outputs are sequential and bounded at 5,000 rows/5 MiB/15 seconds/64 MiB query memory. Trade requests partition disjointly by each of five years and retain only three explicit source partners after reading that bounded reporter/product/year domain. No LIMIT/sample truncation is used. Returned years/identity and unique groups are checked. Schema/coverage/query/resource/publication failures abort the complete bundle; no manifest is published. Final shared read fence verifies one batch and definitions through atomic directory promotion.

Power BI Import uses ten separate mart tables, one ExportFolder parameter, single-direction dimensions for compatible calendar years/countries/partners only. Marketing-year, monthly benchmark and daily quote dates remain separate. No fact-to-fact or auto/bidirectional relationships. Numerical CSV base measures retain Decimal text; Power BI floating numeric precision and display rounding must be validated in Desktop. Precomputed row ratios are diagnostics; DAX aggregation always uses eligible bases.

Actual row counts, EDA reconciliation and Desktop acceptance are recorded separately in DATA_MART_VALIDATION / REPORT_VALIDATION; design is not evidence of runtime success.
